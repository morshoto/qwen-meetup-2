# P3-C Exploration improvement (E1–E3)

This workflow diagnoses saved P3 runs, compares four train-only search
strategies on paired Exploration tasks, then collects independently verified
solutions from other unused Exploration tasks. E2/E3 do not train an adapter,
promote weights, or read Promotion Gate, Monitoring, Validation, Final, or
Public Evaluation labels. `--live` is required for model inference; `--dry-run`
uses the deterministic CPU Fake backend and sandbox.

## Data and selection boundaries

- The ARC Training split remains 400 Exploration / 400 Promotion Gate / 200
  Monitoring at seed 42. The canonical split hash is recorded in each E2 task
  manifest; no split is regenerated by this workflow.
- The exclusion registry combines prior E1/H1/P3-B/P3-C tasks and each run's
  attempted IDs. E2 and E3 select only unused Exploration IDs in fixed split
  order unless an explicit comparison ID list is configured.
- Candidate selection gets public training demonstrations and sandbox
  feedback only. It never receives verifier labels. After selecting a
  candidate, the independent verifier checks every test input and records
  pass/fail as a diagnostic or collection gate.
- E3 is self-generated code filtered using public ARC Training labels. It is
  not unlabeled training. SFT messages contain the task's training pairs and
  test inputs, but never test output grids or verifier feedback.
- Static code checks flag common fixed-grid, task-ID, and external-access
  patterns. These checks are heuristics and do not prove generalization.

## E1: diagnose a saved run

```bash
uv run --locked python -m src.cli.exploration_diagnose \
  --run-dir artifacts/p3c-collect-qwen8b-offset285-9215cfeb3ad7 \
  --output-dir artifacts/e1-diagnosis-p3c-offset285-v2
```

E1 is offline. It writes `summary.json`, `task_diagnostics.jsonl`,
`failure_breakdown.csv`, and `diagnosis.md`. Rates include numerators,
denominators, and unavailable counts. Raw response bodies and reasoning text
are not copied into public reports.

## E2: paired S0–S3 comparison

Profiles are explicit and bounded:

| Profile | Paired tasks | Max calls | Max reserved tokens | Max Docker starts | Run time |
|---|---:|---:|---:|---:|---:|
| E2 Smoke | 2 × 4 strategies | 32 | 250,000 | 120 | 1 hour |
| E2 Full | 5 × 4 strategies | 80 | 500,000 | 240 | 90 minutes |

S0 and S2 use the same code-agent analysis/repair flow; S2 requests thinking
on while other live strategies request it off. The guarded server runs a
tokenizer canary before serving and confirms the effective mode in each
response. S1 generates up to three independent candidates and selects the
first parsed, statically safe candidate that runs on every train input. S3
generates the same candidate prompts but selects by public-train exact matches,
then execution errors and candidate index. S1 does not use its train score to
choose a candidate. Each task/strategy is capped at three total LLM calls.

The machine-readable `selection_policy.yml` and hash are saved before any
request. Full comparison ranks only fully paired tasks by: number of tasks
with every train example matched; macro-average per-task train match rate;
parser and sandbox errors; reserved tokens; then fixed `S0 > S1 > S2 > S3`
order. Test-verifier results are diagnostic only and cannot select or break a
tie. Smoke never selects or freezes a method. Full freezes a method only when
all five tasks have four completed strategy results; the manifest labels a
zero-full-train-match winner `inconclusive_fallback`.

with uncertain outcomes are charged and skipped rather than replayed.

```bash

  --config configs/e2.live.full.yml --live --resume \

```

## E3: collect verified solutions

Live E3 requires a completed, fully paired E2 Full live manifest and its
hash-bound frozen config. It cannot take a Smoke, Fake, or partial E2 result.
E3 Smoke is limited to two new tasks and two verified successes. E3 Collection
targets five distinct successful task IDs and tries at most twenty tasks.

```bash
# Inspect the two-task E3 Smoke plan after a valid E2 Full selection exists.
uv run --locked python -m src.cli.exploration_collect \
  --config configs/e3.live.smoke.yml \
  --selection-dir artifacts/e2-live-full-reselected --check --live

# E3 Smoke needs a fresh 60,000-token guarded ledger.
uv run --locked python -m src.cli.exploration_collect \
  --config configs/e3.live.smoke.yml \
  --selection-dir artifacts/e2-live-full-reselected --live \
  --output-dir artifacts/e3-live-smoke

# E3 Collection is a separate command, capped at 20 tasks / 80 calls / 500,000 tokens.
uv run --locked python -m src.cli.exploration_collect \
  --config configs/e3.live.collection.yml \
  --selection-dir artifacts/e2-live-full-reselected --check --live

uv run --locked python -m src.cli.exploration_collect \
  --config configs/e3.live.collection.yml \
  --selection-dir artifacts/e2-live-full-reselected --live \
  --output-dir artifacts/e3-live-collection
```

Collection re-executes selected code in Docker, checks all public train pairs,
then passes outputs to the independent verifier. Verifier results are never
fed into another model request. A task ID is counted at most once. Interrupted
requests are marked uncertain and skipped on resume:

```bash
uv run --locked python -m src.cli.exploration_collect \
  --config configs/e3.live.collection.yml \
  --selection-dir artifacts/e2-live-full-reselected --live --resume \
  --run-dir artifacts/e3-live-collection
```

E3 writes `config.snapshot.yml`, `source_selection_manifest.json`,
`attempted_tasks.jsonl`, `accepted_solutions.jsonl`,
`rejected_candidates.jsonl`, `sft_train.jsonl`, `collection_manifest.json`,
`budget_ledger.json`, and `artifact_seal.json`. The manifest records rejection
reasons and that Promotion Gate, Monitoring, Validation, Final, and Public
Evaluation were not accessed. The response sidecar remains owner-readable
only. No trainer is invoked, and insufficient successes do not lower any
training gate.

| Run | Tasks / cells | Calls | Reserved tokens | Sandbox starts | Elapsed | Outcome |
|---|---:|---:|---:|---:|---:|---|
| E2 Smoke v1 | 2 / 8 | 20 | 89,418 | 44 | 158 s | 0 verifier passes; S2 truncated twice; smoke only |
| E2 Smoke v2 | 2 / 8 | 21 | 156,692 | 52 | 384 s | 0 verifier passes; S2 truncated twice; smoke only |
| E2 Full | 5 / 20 | 50 | 417,387 | 134 | 887 s | 0 verifier passes and 0 full-train-match tasks for every strategy; S2 truncated on all five tasks |
| E3 Smoke | 2 | 6 | 46,212 | 24 | 49 s | 0 verified tasks; stopped at the sandbox-start cap; 0 SFT records |
| E3 Collection | 19 of 20 | 55 | 496,467 | 199 | 625 s | 0 verified tasks; stopped before a request that could not reserve its token ceiling; 0 SFT records |

E2 Full used 143,167 actual model tokens; E3 Smoke used 12,351 and E3
Collection used 185,087. Both E3 artifacts validate against their seals, keep
`llm_requests.jsonl` and `llm_responses.jsonl` mode `0600`, and record no
training, weight updates, Promotion Gate, Monitoring, Validation, Final, or
Public Evaluation access. The two E3 Smoke task IDs are excluded from the
Collection run. The E2 Full original artifact remains sealed separately from
its corrected S1 selection derivative.

Among E3 candidate records, Smoke ended with one independent-verifier failure,
two candidates not selected by the train-only policy, and one budget stop.
Collection ended with 16 independent-verifier failures, 38 candidates not
selected by the train-only policy, and one budget stop. The verifier outcomes
were recorded after candidate selection and were not fed back to the model.
Inference was local; no hosted API usage charge was incurred (electricity and
local hardware costs were not metered).
